### 🔴 Blocking

1. **[High] The completed-task merge in `scripts/export-backlog.js:525-596` completely bypasses the new `sanitizeApiPayload()` and reintroduces the absolute-path leak this PR exists to fix.** `sanitizeApiPayload` is wired into exactly one call site — the initial per-endpoint fetch loop (`export-backlog.js:521`). The separate "merge completed tasks into tasks.json" block (unchanged by this PR) constructs each task record with `filePath: path.join(completedDir, file)` — `completedDir = path.join(process.cwd(), 'backlog', 'completed')`, i.e. absolute — and `lastModified: new Date().toISOString()`, then writes via raw `JSON.stringify(tasksData)`, no sanitizer call. **Reproduced directly**: created `backlog/completed/task-999.md`, ran `npm run build`, and the committed-shape `dist/api/tasks.json` contained `"filePath": "/private/tmp/brood-pr36-review/backlog/completed/task-999.md"` verbatim — the exact home-directory-path leak from the last review round, now worse because `lastModified` is a fresh wall-clock stamp instead of a filesystem mtime, so it differs between two builds seconds apart on the *same* machine.
   Fix: route this write through `sanitizeApiPayload` too, or — better, since this is the second time a new write path missed it — give each task a repo-relative `filePath` and no `lastModified` at construction time, so the sanitizer is a backstop rather than the only defense for a path that will keep growing new writers.

2. **[High] The same code path also hard-crashes the build — reproduced.** `assertExportConsistent()` (export-backlog.js:173-200, unchanged) requires `statistics.totalTasks === tasks.length === searchTasks.length` and `throw`s "Export consistency check FAILED — refusing to ship dist/" otherwise. The completed-task merge appends to `tasks.json` but never to `search.json`, so the counts diverge the moment one completed task exists. **Reproduced**: same `task-999.md` fixture → `npm run build` exits with `Error: Export consistency check FAILED ... statistics.totalTasks=50 tasks.json=50 search.json(type=task)=49`. Since `preflight.sh` discovers `pnpm run build` as one of its checks, this also means `preflight.sh run` fails and `git-guard.sh pr-create` refuses to open a PR — the brand-new enforcement layer this PR adds would deadlock on the very first commit anyone makes after completing a task, for a reason with nothing to do with what they changed.
   Fix: when appending a completed task, also bump `statistics.totalTasks` and push a matching entry into `search.json` in the same block (or restructure so the merge happens before stats/search are computed, not after).

3. **[Medium — carried over from the first review round, still unfixed for the 3rd consecutive round] `scripts/ci/check-task-yaml.py`'s `SCAN_DIRS` still omits `backlog/milestones`.** Re-verified today: `backlog/milestones/` has 4 files with live YAML frontmatter, actively fetched and exported to the public `/api/milestones/*` endpoint (`export-backlog.js:658-668`). An unquoted `:` in a milestone title breaks the exporter identically to the incident this PR fixes for tasks, and this gate would not catch it there. Verified the failure mode directly: `yaml.safe_load('title: Phase 9: Launch')` → `ScannerError`.
   Fix: add `"backlog/milestones"` to `SCAN_DIRS`. One line.

4. **[Medium] The new enforcement layer is not wired into the documented workflow — it's unreachable.** `plugins/pilot/skills/pilot/phases/run.md:101,111` still instructs `gh pr create` directly. A repo-wide grep for `pr-create|preflight.sh|grade-change.sh|PILOT_SKIP_PREFLIGHT` across every `*.md` in `skills/pilot/` and `plugins/pilot/` returns **zero hits**. The normative doc both new scripts cite as justifying "3 adversarial rounds" (`reference/pre-pr-review.md`) does not exist anywhere in the tree. The one hard-blocking gate this PR adds has no path by which an agent following the actual skill docs would ever invoke it.
   Fix: update `run.md`'s PR-creation steps to `git-guard.sh pr-create`, and either add the missing reference doc or drop the citation.

5. **[Medium, multiple fail-opens] The grading/preflight system undermines its own stated thesis ("mechanical, not self-declared") with several silent fail-open paths** — all independently reproduced by constructing the triggering scenario, not inferred:
   - `grade-change.sh:51-58` — if the base branch can't be resolved locally or on `origin`, `git merge-base` fails silently, all diffs against it are skipped, and an all-committed change can fall through to `GRADE=D "no changes detected"`, exit 0.
   - `grade-change.sh:79-84` — `git diff --numstat` is blind to untracked files (the file's own header already fixed this for the A-grade path; it's still open for the B-grade size/breadth path) — a large new untracked file contributes 0 to `LINES`.
   - `preflight.sh:36-46` — the stamp binds `HEAD`'s sha, but `run` tests whatever is on disk (the working tree), not a clean checkout of `HEAD`. No `git status --porcelain` guard exists, so a dirty tree gets tested and stamped as if it were the clean committed state.
   - `preflight.sh:70-78` — every `scripts/ci/*.sh|*.py` is executed unconditionally, with no check for the executable bit (contradicting the file's own header comment) and no allowlist — `grade-change.sh`'s own A-grade rule in this same PR explicitly acknowledges `*deploy*.sh` patterns can live in adjacent paths.
   - (Found independently by Opus R4, not by R1-R3) `git-guard.sh`'s `pr-create` validates only the **local** `HEAD` sha — there is no check against `@{u}` (the pushed remote branch). Reproduced in a throwaway repo: commit locally without pushing, `preflight.sh run` stamps the local sha, `preflight.sh check` passes — while `origin` still sits at an older, untested commit. `gh pr create` would open a PR for code the checks never ran against.
   None of these are individually catastrophic, but together they mean the three new layers are advisory in exactly the cases that matter, which is the same "fail-open is worse than absent" argument this PR's own commit messages make about the bugs it fixes elsewhere.

### Confirmed but non-blocking

- **[Low]** `preflight.sh:73` — `cmds+=("bash $s")` then `eval`: a filename containing a space or shell metacharacter misparses (not just a malicious-repo concern — a legitimately named `check docs.sh` would already break). Use arrays, drop `eval`.
- **[Low]** `grade-change.sh:66` — `/tmp/pilot-graded-files.$$` is a predictable temp filename created with `>` (follows symlinks); use `mktemp`.
- **[Low]** `git-guard.sh:143-148` — `grade` read from the stamp is used unvalidated in a `case`; any value outside `A|B|C|D` matches neither arm and prints nothing, silently.
- **[Low]** `export-backlog.js:78` — `REPO_ROOT = process.cwd()` rather than the git toplevel; an unrecognized path prefix is passed through verbatim rather than redacted (fails open, not closed) — e.g. a `rootConfigPath` outside the repo would ship as-is.
