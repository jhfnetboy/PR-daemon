### 值得在合并前顺手带上的一行

**[Med] `render-gate.ts:263` — `modifierHit(t)` 扫的是整条消息，包括指令**之后**的分句。** 于是修饰语属于**另一个分句**时会误拦。实测 18 例，最典型的：
```
误拦  「logo 以后再定，先出图吧」      「材质回头再说，出图吧」
误拦  「价格我们下次谈，就这个，出图吧」  "The logo can come later, go ahead"
误拦  「确认了，出图吧」「我确认了，直接出图」「等了三天了，直接出图吧」
```
最后一组最刺眼：`确认(?:了|后)` 拦掉了中文里**最典型的「确认后下单」说法**，而这个文件的第二条放行条件恰恰叫 `confirmedDirection`。

把作用域收成「本分句 + 之前的分句」是**免费的**，我实测过：
```ts
if (modifierHit(cs.slice(0, i + 1).map(x => x.core).join('，'))) return false;
```
测试仍**全部通过**，`if the price is ok, go ahead` / `以后再做图` / `他说「出图吧」` 三条该拦的仍然拦住。
⚠️ **但它救不回「确认了，出图吧」** —— 那条需要真正的前置分句作用域规则，属于后续 issue，别指望这一行解决。

### 既有的洞（新旧都有，本轮未触碰，建议后续处理）

- **[Med] `:208` — `reported` 这一类实际覆盖率约 1/22。** 它只匹配紧贴 **说** 的说话人，且没有别的引述动词。实测仍触发：`他们说出图吧`/`他跟我说出图吧`/`老板刚才说出图吧`/`客户在邮件里说直接出图`/`甲方说出图吧`/`他让我出图`/`老板要求出图`/`老板叫我做张图`/`they want me to go ahead`/`the client asked us to go ahead`/`boss says go ahead`/`per the boss, go ahead`。本轮点名的那 4 条修好了，类别本身基本没生效。
- **[Med] `:168-169` vs `:155` — 前后缀锚点不对称。** 英文触发词以 `${TAIL}$` 收尾，所以任意尾部垃圾**免词表**就被挡掉（`go ahead tomorrow`/`go ahead xyzzy` 都 false）；但中文触发词有 `$` **没有 `^`**，任意前缀直接放行：`xyzzy出图吧` → **true**。于是 MODIFIERS 成了中文前缀这一侧**唯一**的守卫，而它是手工词表：`明天出图吧`/`周一出图吧`/`下午出图吧`/`有空出图吧`/`看情况出图吧` 全部 true。
- **[Med] `:204`** — 同理，`conditional` 在英文侧也是手工词表：`assuming the price works, go ahead`/`in case you have time, go ahead`/`provided the moq is fine, go ahead`/`pending approval, go ahead` 5/6 true。
- **[Low] `:208` — `(?!I\b)` 是死代码**，16 条语料上零行为差异：`(?:he|she|they|boss|client|customer|my\s+\w+)` 里没有任何分支能以 `i` 开头。第一人称是靠**没被列进候选**排除的，不是靠这个 lookahead。注释里那句「⚠️ 排除第一人称」声称了一个代码并未提供的保护 —— 哪天有人往候选里加 `i`，保护会静默消失。
- **[Low] `:128`** — 上一轮补的 ASCII `.` / 破折号 / 冒号分隔符在整个语料上是死的（删掉测试仍绿，`go ahead. no wait.` 靠 `${TAIL}$` 就已经拦住）。`:191` 的注释已经承认这点，但既没删也没补一条必须靠它的用例。

### 一条设计note（留给以后的 PR，不是这个）

震荡被挪到了更好的位置，但**搬家只搬了一半**：`${TAIL}$` 让英文的**后缀**修饰语免词表，而**前缀**修饰语在两种语言里都没有对应机制，于是 MODIFIERS 成了中文触发词前面一张孤零零的手工前缀词表。第五轮会加 `明天/周一/有空`，第六轮会发现 `礼拜一/月底/等下` —— 词表churn 比锚点 churn 便宜，但仍是 churn。

真正能终结它的是**对称**：给中文触发词一条前置作用域规则（前缀必须为空，或落在一张很小的「立即性」白名单里：`先/直接/马上/就`），就像 `${TAIL}$` 给英文触发词的后置规则那样。到那时 `modifierHit` 可以收缩到只看指令分句，上面那 18 处便宜方向的回归也就大部分自动消失了。
