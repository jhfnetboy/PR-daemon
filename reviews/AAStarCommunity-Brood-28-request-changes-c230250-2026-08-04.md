3. **[Medium] `skills/pilot/phases/run.md` §0 + `skills/pilot/scripts/git-guard.sh:24`** — `PILOT_PROTECTED` (the repo's real `base_branch`/`integration_branch`/`protect_patterns` from `.pilot.yml`) is delivered via a bare `export` in one documented step and consumed by `git-guard.sh` in later, separately-invoked steps. ### Strategic (architectural, not single-line — for awareness, not gating)

- All four blocking findings above are symptoms of one design choice: the PR's central safety claim ("危险动作全走脚本层硬拦截…不靠模型临场判断" — dangerous actions are hard-blocked at the script layer, not left to model judgment) doesn't fully hold at the boundary. `allowed-tools` grants unrestricted `Bash`, so *choosing to invoke* `git-guard.sh` at all remains a prose convention the agent could skip, and the one piece of per-repo state the rails depend on (`PILOT_PROTECTED`) is delivered by a mechanism that doesn't reliably survive a tool-call boundary. For a genuinely unattended overnight loop, the enforceable version would be harness-level — `permissions.deny` entries (`Bash(git push:*)`, `Bash(git add:*)`, `Bash(gh pr merge:*)`) or a `PreToolUse` hook shipped by `install.sh` — rather than a script the agent can simply choose not to call.
- Protected-branch config is expressed three different ways across the skill (`.pilot.yml` YAML fields / `PILOT_PROTECTED` env var / `--protect` flag) with the model as the manual transcoder, and `phases/status.md` never performs that transcode at all. One shared reader consumed identically by every script would close this whole class of gap (including the untrimmed-CSV Low above) in one change.
- `safe-cleanup.sh` and `pr-monitor.sh` are 95–99%-similarity pure renames in this diff (only an echo string / name references changed) — their safety-critical invariants ("only delete merged+clean branches"; whether CI-checks-passed is actually verified before merge) are inherited unchanged from `repo-pilot` and were **not** re-audited this round, even though `README.md`/`SKILL.md` lean on them as load-bearing safety guarantees.

### Rejected

- "`git-guard.sh` `merge-pr` `--squash` bypasses protection" (R1a) — `--squash` is a merge-strategy flag only; the `base == --integration` check is still enforced before `exec`. No bypass exists. Verified via `gh pr merge --help`.

No injection surface.
